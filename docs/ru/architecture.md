# Архитектура

## Обзор

Alva — PWA на Blazor WebAssembly с серверной частью на ASP.NET Core. Интерфейс — общая
библиотека для двух оболочек: прод-версии (данные по HTTP) и демо (данные в браузере).

```
Браузер (Blazor WASM)                 Сервер (ASP.NET Core)
┌───────────────────────────┐        ┌───────────────────────────┐
│ Alva.Client / .Demo        │        │ Alva.Api                  │
│   └ Alva.Client.UI         │  HTTP  │   ├ Minimal API endpoints │
│        └ IApiService       │ ─────► │   ├ cookie-аутентификация │
│             ├ ApiServiceHttp│       │   └ доступ по командам   │
│             └ ApiServiceLocalStorage│      │ Alva.Infrastructure       │
└───────────────────────────┘        │   └ EF Core → PostgreSQL  │
                                     └───────────────────────────┘
```

## Проекты (`src/`)

| Проект | Назначение |
| :-- | :-- |
| `Alva.Domain` | Сущности и правила предметной области |
| `Alva.Contracts` | DTO и контракты запросов/ответов, общие для сервера и клиента |
| `Alva.Infrastructure` | `DbContext`, конфигурация EF Core, миграции |
| `Alva.Api` | Minimal API: эндпоинты, аутентификация, права, раздача WASM |
| `Alva.Client.UI` | Библиотека интерфейса: страницы, макет, модели, `IApiService`, `AlvaSession` |
| `Alva.Client` | Прод-оболочка: реализация `IApiService` поверх HTTP |
| `Alva.Client.Demo` | Демо-оболочка: реализация `IApiService` на `localStorage` |
| `Alva.Integrations.Abstractions` | Контракты внешних источников задач |
| `Alva.Integrations.YandexTracker` | Интеграция с Яндекс Трекером как источником задач |
| `Alva.Theme.Alva` | Тема Alva Stitch на базе Fluent UI 2 |
| `Flare.Components.Gantt` | Внешний NuGet-пакет Flare, используемый Alva.Client.UI |

## Поток данных

Страницы зависят от `AlvaSession` — фасада над `IApiService`. Реализация выбирается при
сборке: прод-оболочка регистрирует HTTP-сервис, демо — локальный. Поэтому страницы не
знают, откуда приходят данные, и прод- и демо-версии используют один и тот же интерфейс.

`IApiService` покрывает сессию (вход, выход, выбор пространства и команды), чтение и
запись ресурсов команды, импорт и экспорт. `AlvaSession` добавляет удобные обёртки
(`Get<T>`, `Send`, `Save`) и контекст списка задач.

## Локализация

Строки интерфейса лежат в `Alva.Client.UI/Resources/AppStrings.resx` (нейтральный, английский) и
`AppStrings.ru.resx` (русский). Компоненты и классы используют сгенерированные свойства
`AlvaStrings`: их проверяет компилятор, а ключи перечислены в resx. `Strings.T(key)` остаётся
только для ключей, собираемых во время выполнения (`plural.*` и `reason.*`); отсутствующий
ключ возвращается как есть, поэтому интерфейс не ломается. `CultureService` выбирает язык:
`localStorage` → браузер → английский. Переключатель EN/RU сохраняет выбор на устройстве.

## Серверная часть

- **Эндпоинты** сгруппированы по областям: аутентификация, пространства и команды,
  участники, справочник, проекты, спринты, задачи, назначения, ёмкость, риски,
  автобаланс, данные, уведомления.
- **Аутентификация** — cookie (ASP.NET Core Identity для хеширования паролей).
- **Права** — членство в пространстве и командах; владелец пространства управляет
  участниками; для команды включается opt-in матрица прав по областям.
- **Схема** — миграции EF Core при запуске (`Database:MigrateOnStartup`); для SQLite —
  `EnsureCreated`.

## Демо-версия

Демо работает без сервера: `ApiServiceLocalStorage` держит данные в `localStorage` и повторяет
контракт `IApiService`. Это позволяет показывать приложение на GitHub Pages, не поднимая
API и базу.

## Диаграмма Ганта

`Flare.Components.Gantt` — самостоятельный компонент таймлайна: ось, дорожки, свёртка,
каскад, критический путь, проверка циклов, связи и внешнее перетаскивание. Он не знает о
приложении и используется страницами «Гантт по задачам», «Гантт по людям» и доской
планирования спринта.
